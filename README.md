# MGMT radiomics: сравнение методов отбора признаков

Проект сравнивает три подхода к отбору радиомических признаков для анализа
метилирования промотора MGMT: F-score по Le, XGBoost → GA-RF по Do и
MI → RF-RFE по мотивам Calabrese. Их проверили на доступной reference-таблице,
затем применили к одной и той же когорте UPenn-GBM. Основное сравнение
использует очистку и отбор признаков **внутри обучающих фолдов**.

## Данные и подход

| Набор | Пациенты | Признаки | Назначение |
|---|---:|---:|---|
| Reference (таблица Do) | 53 | 724 исходных, 704 после удаления столбцов с пропусками | Проверка методов; опубликованный top-9 Le воспроизведён точно. Прогон Calabrese здесь является адаптацией, исходной UCSF-матрицы в проекте нет. |
| UPenn-GBM | 256 (148 unmethylated, 108 methylated) | 1728 исходных структурных признаков CaPTk | Основное сравнение методов, бейзлайнов и устойчивости. |

Клиническая таблица UPenn содержит 671 пациента. Из них 291 имеет однозначный
MGMT-статус; после объединения 12 блоков радиомики остаются 256. Потеря 35
пациентов приходится на три блока FLAIR. Использованы FLAIR, T1GD, T1 и T2
для областей ED, ET и NC; DTI и DSC не использованы. При очистке **всей**
матрицы для раннего ознакомительного анализа осталось 1480 признаков.
В основной оценке очистка проводится заново на обучающих пациентах каждого
фолда, и число признаков может различаться между фолдами. Источники меток,
таблицы и подробная трассировка приведены в
[протоколе UPenn](docs/UPENN_PREPROCESSING.md). Это выгрузка CaPTk:
версия PyRadiomics к ней не относится, фактическая версия CaPTk не установлена.

| Метод отбора | Действие в основном сравнении |
|---|---|
| Le/F-score | Девять лучших признаков по F-score. |
| Do/XGBoost → GA-RF | Кандидаты по XGBoost gain, затем подмножество по GA с внутренней RF accuracy. |
| Calabrese-inspired MI → RF-RFE | До 1024 кандидатов по mutual information, затем 32 признака по RF-RFE. |

Для GA и RF-RFE применён вычислительно сокращённый профиль `practical`.
Это проверка подходов из статей, а не точное воспроизведение всех настроек
их экспериментов. Ссылки на публикации и найденный авторский код:
[SOURCES.md](docs/SOURCES.md).
В этом профиле GA использует 12 особей, 5 поколений, RF из 50 деревьев и
внутреннюю 3-fold CV; RF-RFE использует RF из 100 деревьев и шаг удаления
64 признаков. Эти параметры отличаются от более дорогого профиля `legacy`.

## Основная оценка на UPenn

Пять одинаковых стратифицированных **внешних** фолдов используются для всех
методов. В каждом внешнем обучающем фолде внутренняя пятифолдовая CV выбирает
`C` L2 Logistic Regression по AUROC. Удаление констант и точных дубликатов,
импутация медианой, отбор и `StandardScaler` обучаются только на своих
обучающих данных. Каждый внешний проверочный пациент получает один прогноз.

Сравниваются также модель без отбора и случайные наборы из 9, 32 и
совпадающего с GA числа признаков. GA запущен с пятью заранее заданными
сидами `11, 22, 33, 44, 55`, случайные варианты — по 20 раз. Основные
парные сравнения используют
фиксированный `repeat=0`; лучший сид задним числом не выбирается. Основная
метрика ниже — AUROC объединённых out-of-fold (OOF) прогнозов. Интервалы
получены из 2000 перевыборок пациентов по **готовым прогнозам**.

| Метод | Признаков в среднем | OOF AUROC, повтор 0 | 95% ДИ | AUROC внешних фолдов, среднее ± SD | Средний OOF AUROC ± SD по повторам |
|---|---:|---:|---:|---:|---:|
| F-score | 9 | 0.423 | 0.355–0.490 | 0.408 ± 0.070 | — |
| MI → RF-RFE | 32 | 0.462 | 0.391–0.531 | 0.421 ± 0.101 | — |
| XGBoost → GA-RF | 116.2 | 0.464 | 0.394–0.534 | 0.448 ± 0.047 | 0.491 ± 0.019 (5 сидов) |
| Все признаки, L2 Logistic Regression | 1479.2 | 0.434 | 0.367–0.506 | 0.432 ± 0.032 | — |
| Случайные 9 | 9 | 0.465 | 0.394–0.538 | 0.457 ± 0.093 | 0.459 ± 0.036 (20 повторов) |
| Случайные 32 | 32 | 0.473 | 0.405–0.544 | 0.478 ± 0.041 | 0.456 ± 0.029 (20 повторов) |
| Случайный набор размера GA | 116.2 | 0.479 | 0.405–0.547 | 0.416 ± 0.099 | 0.459 ± 0.046 (20 повторов) |

Среднее ± SD по внешним фолдам рассчитано для фиксированного `repeat=0`
из пяти значений AUROC на проверочных частях.

| Метод | Δ AUROC к случайному K (95% парный ДИ) | Δ AUROC к модели без отбора (95% парный ДИ) |
|---|---:|---:|
| F-score | −0.042 [−0.128; 0.046] | −0.012 [−0.095; 0.069] |
| MI → RF-RFE | −0.010 [−0.095; 0.076] | +0.028 [−0.055; 0.112] |
| XGBoost → GA-RF | −0.015 [−0.113; 0.086] | +0.029 [−0.049; 0.106] |

Все показанные интервалы разницы включают ноль; во всех девяти запланированных
парных сравнениях p-value DeLong после поправки Holm равен 1.0. **Убедительного
преимущества отбора не обнаружено**. Это не доказывает равенство методов.
DeLong для OOF-прогнозов разных обученных моделей — приближённая
исследовательская проверка. Независимого тестового набора в этом эксперименте
нет. Причины низкого AUROC пока не исследованы.

## Устойчивость отбора

Каждый из трёх селекторов заново обучен на 20 стратифицированных
бутстрэп-выборках пациентов; очистка тоже выполняется заново. Внутри
каждого метода для 190 пар выбранных наборов посчитан Jaccard.

| Метод | Признаков за выборку | Средний Jaccard | Медиана | Разных признаков за 20 выборок |
|---|---:|---:|---:|---:|
| F-score | 9 | 0.027 | 0.000 | 132 |
| MI → RF-RFE | 32 | 0.047 | 0.049 | 370 |
| XGBoost → GA-RF | 98.9 в среднем | 0.070 | 0.068 | 865 |

Наборы признаков чувствительны к составу пациентов. GA выбирает больше
признаков, поэтому его Jaccard нельзя считать прямым свидетельством большей
устойчивости. Пары выборок зависимы; их 190 значений не являются
независимыми экспериментами. Протокол и ограничения описаны в
[SELECTION_STABILITY.md](docs/SELECTION_STABILITY.md). 

Сопоставление
конкретных признаков reference ↔ UPenn по названиям метрик показало малое
пересечение: в пяти внешних фолдах средний Jaccard составил **0.014** для
GA-RF и **0.013** для MI → RF-RFE при сравнении только одинаково обозначенных
областей ED/ET. Для F-score такая оценка не определена: ни один из его девяти
reference-признаков не вошёл в сопоставимую часть пространства. При условном
сопоставлении NET ↔ NC Jaccard составил **0.030**, **0.007** и **0** для
GA-RF, MI → RF-RFE и F-score соответственно. Эти числа относятся к
**отдельным признакам**, а не к совпавшим семействам; соответствие формул
извлечения и областей NET/NC не подтверждено. Таблицы, покрытие словаря и
результаты 20 бутстрэп-выборок приведены в
[SELECTION_STABILITY.md](docs/SELECTION_STABILITY.md).

## Запуск и файлы

Требуется Python 3.11+. Установка из корня репозитория в Git Bash:

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -e .
```

При наличии исходных локальных таблиц основной эксперимент воспроизводится
следующими командами:

```bash
./.venv/Scripts/python.exe scripts/build_upenn.py
./.venv/Scripts/python.exe scripts/run_upenn_nested_cv.py \
  --random-repeats 20 --output results/upenn/nested_cv/repeats_20
./.venv/Scripts/python.exe scripts/run_upenn_selection_stability.py --draws 20
```

`build_upenn.py` создаёт как исходную объединённую матрицу
`data/processed/upenn/upenn_structural_raw.csv` для основного анализа, так и
ранее очищенную `upenn_clean.csv` для ознакомительного. Завершённые фолды и
бутстрэп-выборки сохраняются в checkpoints и могут использоваться при
повторном запуске **с теми же данными, кодом и настройками**. Параметр
`--quick` служит только для проверки работы кода. Скрипты `run_all.py`,
`run_reference.py`, `run_upenn.py`, `evaluate_upenn_selected.py` и
`build_report.py` относятся к раннему ознакомительному анализу.

Подробные списки выбранных признаков и ранние сравнения сохранены в
[results_summary.md](docs/results_summary.md); там отбор выполнялся на всей
UPenn-матрице **до** downstream CV. AUROC около 0.60 из этого анализа нельзя
сравнивать с основной оценкой как результат того же протокола.

Данные в `data/raw/`, `data/processed/` и выходы в `results/upenn/`
игнорируются Git. Таблицы `summary.csv`, `fold_metrics.csv`,
`oof_predictions.csv`, `method_inference.csv`, `paired_comparisons.csv` и
`stability_summary.csv` остаются локально. Числа в этом README записаны по
локальным результатам; для независимой проверки нужно отдельно сохранить
эти CSV вместе с `run_metadata.json` и исходными данными.
