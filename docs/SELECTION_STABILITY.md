# Устойчивость отбора признаков на UPenn

Для проверки устойчивости каждый метод прогнан на 20
бутстрэп-выборках пациентов и измерено пересечение выбранных признаков.
Используется та же когорта из **256 пациентов** и исходные structural
radiomics, что и в nested CV. AUROC здесь повторно не оценивается.

В каждой из 20 выборок пациенты выбираются **с возвращением отдельно для
каждого класса MGMT**: численность классов остаётся исходной. Для трёх
методов используются одни и те же выборки. На каждой выборке отдельно
вычисляются константы, точные дубликаты, медианы для импутации и затем
отбираются признаки. Сид самого алгоритма фиксирован: измеряем изменение
набора признаков из-за состава пациентов, а не из-за смены сида GA или MI.
Профиль `practical` соответствует полному прогону nested CV; профиль
`legacy` требует намного больше ресурсов.

Запуск из корня проекта в **Git Bash**:

```bash
./.venv/Scripts/python.exe scripts/run_upenn_selection_stability.py \
  --methods le_fscore calabrese_mi_rfe \
  --draws 20
```

После этих методов отдельно запускается более долгий GA с теми же данными,
сидами и выходной папкой:

```bash
./.venv/Scripts/python.exe scripts/run_upenn_selection_stability.py \
  --methods do_xgb_ga \
  --draws 20
```

После второй команды общая сводка включает все три завершённых метода.
Можно запустить всё одной командой без `--methods`. Каждый завершённый
метод/бутстрэп сохраняется и при перезапуске используется повторно.
При изменении входного CSV, настроек или кода отбора нужно выбрать **новую
выходную папку**, чтобы не смешивать результаты разных протоколов.

Выход находится в `results/upenn/selection_stability/bootstrap_20/`:

- `bootstrap_indices.json` — точные индексы выбранных пациентов;
- `checkpoints/<method>/draw_*.json` — отобранные признаки каждой выборки;
- `selected_features_by_draw.csv` — списки признаков по выборкам;
- `selection_frequency.csv` — частота отбора каждого признака;
- `pairwise_jaccard.csv` — пересечение, объединение и Jaccard для каждой
  пары выборок (190 пар на метод);
- `stability_summary.csv` — среднее, медиана, SD и диапазон Jaccard,
  размер выбранных наборов и общее число разных отобранных признаков.

190 попарных сравнений **зависимы**: одна и та же выборка входит во многие
пары. SD описывает разброс этих пар, но не является доверительным
интервалом на 190 независимых наблюдениях. Jaccard зависит также от
размера наборов, поэтому анализируем его вместе с
`mean_selected_features`.

При бутстрэпе один пациент встречается несколько раз. Встроенная CV
GA-RF и RF-RFE не группирует эти копии по исходному пациенту: внутренние
оценки могут быть оптимистичными. Здесь они служат только алгоритму отбора;
оценивать качество предсказания по ним нельзя. Отдельный бутстрэп из
`method_inference.csv` пересчитывал AUROC для **готовых** OOF-прогнозов
2000 раз и не обучал селекторы заново.

## Пересечение reference ↔ UPenn

В reference есть имена вроде `TEXTURE_GLRLM_ED_T2_GLV`, а в UPenn
используются имена CaPTk вроде
`T2_ED_GLRLM_Bins-16_Radius-1_...`. Область `NET` из reference также
нельзя автоматически приравнивать к `NC` из UPenn без проверки правил
сегментации. Совпадение названий семейств, последовательностей и областей
ещё не означает тождество формул и численных признаков.

Для содержательного межкогортного Jaccard сначала нужен подтверждённый
словарь соответствий: последовательность, сегмент, конкретная формула,
квантование и версии программ извлечения. В этой итерации такой словарь
**не установлен**. Нулевое пересечение исходных строковых имён нельзя
выдавать за нулевую переносимость признаков.

### Сравнение доступных блоков без повторного обучения

Скрипт использует уже сохранённые выбранные признаки по внешним фолдам
основного nested CV и по 20 бутстрэп-выборкам. Для каждого метода он
сопоставляет результаты на reference и UPenn. Данные пациентов не загружаются:
от UPenn нужен только заголовок исходной таблицы и её SHA256 для сверки с
`run_metadata.json`. Запуск из корня репозитория в Git Bash:

```bash
./.venv/Scripts/python.exe scripts/compare_reference_upenn.py
```

Ожидаются локальные файлы:

- `data/processed/upenn/upenn_structural_raw.csv`;
- `results/upenn/nested_cv/repeats_20/selected_features_by_fold.csv`;
- `results/upenn/selection_stability/bootstrap_20/selected_features_by_draw.csv`;
- `run_metadata.json` в обоих каталогах результатов.

Если результаты сохранены в другом месте, передайте `--raw`, `--nested-dir`
и/или `--stability-dir`. Для одного источника используйте `--source nested`
или `--source bootstrap`. Команда только читает результаты; GA заново не
запускается.

Имена приводятся к двум описательным уровням:

1. **Строгий блок:** последовательность × область × семейство признаков.
   Сопоставляются только ED и ET с одинаковыми обозначениями областей;
   `T1Gd` и `T1GD` считаются обозначениями одной последовательности.
2. **Широкий блок:** последовательность × семейство, без учёта области.
   `NET` и `NC` при этом остаются в исходных строках и **не признаются**
   эквивалентными сегментами; этот уровень менее специфичен.

На каждом уровне Jaccard считается между **множествами названий блоков**,
а не множествами отдельных радиомических признаков. Размеры блоков и
доступность соответствующих блоков среди сырых UPenn-столбцов показаны
отдельно. Строгая метрика опускает `NET` и `NC`, поэтому может скрыть
межкогортное расхождение по этим областям. Значения по фолдам/выборкам
зависят друг от друга и не являются независимыми оценками.

Выход: `results/upenn/reference_overlap/` (игнорируется Git):

- `summary.csv` — средние описательные показатели по методу и источнику;
- `comparison_by_run.csv` — пересечение для каждого внешнего фолда и каждой
  бутстрэп-выборки, включая все пять сидов GA в nested CV;
- `shared_blocks.csv` — названия совпавших блоков и признаки обеих когорт;
- `possible_metric_matches.csv` — одинаковые метки конкретной метрики в
  одинаковом строгом блоке; **кандидаты** для ручной проверки, не
  подтверждённое совпадение формулы или реализации;
- `reference_availability.csv` — какие блоки reference присутствуют в
  заголовке исходной UPenn-матрицы; наличие не гарантирует, что столбец
  сохраняется после очистки внутри фолда;
- `feature_name_audit.csv` — разбор имён, включая неподдерживаемые семейства
  и несопоставленные `NET`/`NC`;
- `run_metadata.json` — хеши входов и настройки, с которыми делалось сравнение.

Интерпретировать Jaccard этих блоков как **переносимость конкретных
признаков** нельзя. Для такого утверждения потребуется вручную подтвердить
соответствие сегментов, формул, параметров квантования и версий извлечения
и только затем считать пересечение по утверждённой карте отдельных признаков.

### Пересечение отдельных выбранных признаков по названиям метрик

Предыдущее сравнение блоков не отвечает на вопрос о совпадении **отдельных**
выбранных признаков. Для этого запустите:

```bash
./.venv/Scripts/python.exe scripts/compare_reference_upenn_features.py
```

Входы те же; повторное обучение не требуется. Словарь явно сопоставляет
аббревиатуры метрик reference с именами CaPTk в UPenn (например,
`GLSZM_SZE` с `GLSZM_SmallZoneEmphasis`). Ключ сравнения включает
последовательность, область, семейство и **конкретную метрику**.
Сравниваются только названия, поддержанные словарём и присутствующие в
исходных матрицах **обеих** когорт. Неоднозначные совпадения нескольких
столбцов на один ключ исключаются. Гистограммные `BinN` исключены:
соответствие `Frequency` и `Probability` не подтверждено.

Выход находится в `results/upenn/reference_feature_overlap/`:

- `summary.csv` — среднее пересечение и Jaccard по запускам каждого метода;
- `overlap_by_run.csv` — числа по каждому фолду, сиду GA и бутстрэп-выборке;
- `shared_individual_features.csv` — **пары конкретных выбранных признаков**;
- `candidate_raw_feature_map.csv` — все пары доступных исходных столбцов;
- `reference_selected_coverage.csv` — причины исключения каждого выбранного
  reference-признака;
- `run_metadata.json` — хеши входов и ограничение трактовки совпадений.

`strict_ed_et` сопоставляет только ED/ET; `exploratory_NET_as_NC` дополнительно
считает `NET` и `NC` условно совпавшими областями для анализа чувствительности.
Это **не подтверждает**, что их сегментация одинакова. Jaccard считается по
отдельным *сопоставимым по имени* выбранным метрикам в общей доступной
матрице; число таких признаков и покрытие reference нужно приводить рядом
с Jaccard. Если у метода нет ни одного сопоставимого reference-признака,
оценка Jaccard остаётся пустой, а не равной нулю. Даже совпавшая метрика не
доказывает равенство формул, квантования и версии экстрактора.

#### Полученные результаты

Сравнение выполнено по сохранённым спискам selected features: 5 внешних
фолдов для F-score и MI → RF-RFE, 5 фолдов × 5 сидов для GA-RF; отдельно —
по 20 бутстрэп-выборкам для каждого метода. В `strict_ed_et` общий словарь
содержит 176 кандидатов по названиям признаков, при условном NET ↔ NC — 264.
Это количество доступных пар столбцов, **не число совпавших выбранных
признаков**.

| Сценарий | Метод | Сопоставимых reference | Совпадений на внешний фолд, среднее | Jaccard внешних фолдов, среднее | Совпадений на бутстрэп, среднее | Jaccard бутстрэпа, среднее |
|---|---|---:|---:|---:|---:|---:|
| ED/ET | F-score | 0/9 | 0 | — | 0 | — |
| ED/ET | GA-RF | 5/21 | 0.24 | 0.014 | 0.20 | 0.015 |
| ED/ET | MI → RF-RFE | 12/32 | 0.20 | 0.013 | 0.20 | 0.014 |
| ED/ET + условное NET ↔ NC | F-score | 6/9 | 0 | 0 | 0 | 0 |
| ED/ET + условное NET ↔ NC | GA-RF | 11/21 | 0.92 | 0.030 | 0.65 | 0.024 |
| ED/ET + условное NET ↔ NC | MI → RF-RFE | 25/32 | 0.20 | 0.007 | 0.35 | 0.012 |

Например, в строгом сравнении у GA-RF совпадали
`TEXTURE_GLCM_ED_T2_Homogeneity` и
`T2_ED_GLCM_Bins-16_Radius-1_Homogeneity` (в 4 из 25 запусков nested CV).
При условном NET ↔ NC чаще встречалась пара
`TEXTURE_GLSZM_NET_T1_SZE` ↔
`T1_NC_GLSZM_Bins-16_Radius-1_SmallZoneEmphasis` (в 9 из 25 запусков GA-RF).
Весь перечень пар и отдельные фолды доступны в
`shared_individual_features.csv` и `overlap_by_run.csv`.

Пересечение **названий отдельных метрик** низкое и в основной внешней CV,
и в бутстрэпе. Для F-score строгий Jaccard не оценивается: исключены все
девять его reference-признаков; запись «ноль» здесь была бы неверной.
Средние Jaccard описывают запуски, которые не являются независимыми:
в GA одни и те же внешние фолды используются с разными сидами.
Поскольку методы выбирают разное число признаков, сами значения Jaccard
не следует трактовать как доказательство большей переносимости одного метода.
Вывод о тождестве радиомических признаков между когортами потребует проверки
сегментации, формул, квантования и программ извлечения; отсутствие совпадений
в текущем словаре также не доказывает отсутствие общего биологического сигнала.
