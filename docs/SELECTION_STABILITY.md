# Устойчивость отбора признаков на UPenn

Эксперимент отвечает на запрос руководителя: прогнать каждый метод на 20
бутстрэп-выборках пациентов и измерить пересечение выбранных признаков.
Используется та же когорта из **256 пациентов** и исходные structural
radiomics, что и в nested CV. AUROC здесь повторно не оценивается.

В каждой из 20 выборок пациенты выбираются **с возвращением отдельно для
каждого класса MGMT**: численность классов остаётся исходной. Для трёх
методов используются одни и те же выборки. На каждой выборке отдельно
вычисляются константы, точные дубликаты, медианы для импутации и затем
отбираются признаки. Сид самого алгоритма фиксирован: измеряем изменение
набора признаков из-за состава пациентов, а не из-за смены сида GA или MI.
Профиль `practical` соответствует полному прогону nested CV; профиль
`legacy` требует намного больше ресурсов.

Запуск из корня проекта в **Git Bash**:

```bash
./.venv/Scripts/python.exe scripts/run_upenn_selection_stability.py \
  --methods le_fscore calabrese_mi_rfe \
  --draws 20
```

После этих методов отдельно запускается более долгий GA с теми же данными,
сидами и выходной папкой:

```bash
./.venv/Scripts/python.exe scripts/run_upenn_selection_stability.py \
  --methods do_xgb_ga \
  --draws 20
```

После второй команды общая сводка включает все три завершённых метода.
Можно запустить всё одной командой без `--methods`. Каждый завершённый
метод/бутстрэп сохраняется и при перезапуске используется повторно.
При изменении входного CSV, настроек или кода отбора нужно выбрать **новую
выходную папку**, чтобы не смешивать результаты разных протоколов.

Выход находится в `results/upenn/selection_stability/bootstrap_20/`:

- `bootstrap_indices.json` — точные индексы выбранных пациентов;
- `checkpoints/<method>/draw_*.json` — отобранные признаки каждой выборки;
- `selected_features_by_draw.csv` — списки признаков по выборкам;
- `selection_frequency.csv` — частота отбора каждого признака;
- `pairwise_jaccard.csv` — пересечение, объединение и Jaccard для каждой
  пары выборок (190 пар на метод);
- `stability_summary.csv` — среднее, медиана, SD и диапазон Jaccard,
  размер выбранных наборов и общее число разных отобранных признаков.

190 попарных сравнений **зависимы**: одна и та же выборка входит во многие
пары. SD описывает разброс этих пар, но не является доверительным
интервалом на 190 независимых наблюдениях. Jaccard зависит также от
размера наборов, поэтому анализируем его вместе с
`mean_selected_features`.

При бутстрэпе один пациент встречается несколько раз. Встроенная CV
GA-RF и RF-RFE не группирует эти копии по исходному пациенту: внутренние
оценки могут быть оптимистичными. Здесь они служат только алгоритму отбора;
оценивать качество предсказания по ним нельзя. Отдельный бутстрэп из
`method_inference.csv` пересчитывал AUROC для **готовых** OOF-прогнозов
2000 раз и не обучал селекторы заново.

## Пересечение reference ↔ UPenn

В reference есть имена вроде `TEXTURE_GLRLM_ED_T2_GLV`, а в UPenn
используются имена CaPTk вроде
`T2_ED_GLRLM_Bins-16_Radius-1_...`. Область `NET` из reference также
нельзя автоматически приравнивать к `NC` из UPenn без проверки правил
сегментации. Совпадение названий семейств, последовательностей и областей
ещё не означает тождество формул и численных признаков.

Для содержательного межкогортного Jaccard сначала нужен подтверждённый
словарь соответствий: последовательность, сегмент, конкретная формула,
квантование и версии программ извлечения. В этой итерации такой словарь
**не установлен**. Нулевое пересечение исходных строковых имён нельзя
выдавать за нулевую переносимость признаков.
